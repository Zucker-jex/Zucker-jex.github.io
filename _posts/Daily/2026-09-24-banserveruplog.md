## v1.0 —— 项目初始版本

**发布时间**：2026-09-21 前（项目基础版本）

**核心功能首次上线**

### 用户系统

- 服主注册（用户名、密码、QQ、邮箱）
- 注册后需管理员审批才能使用
- 登录 / 登出
- 账号状态管理（待审批 / 正常 / 已禁用）
- 角色分级（服主 / 管理员）

### 服务器管理

- 服主可创建自己的服务器
- 支持重命名、删除服务器
- 一个账号可拥有多个服务器

### 封禁管理

- 提交封禁记录（SteamID、游戏用户名、原因、封禁时间、解封时间）
- 支持永久封禁和临时封禁
- 编辑已提交的封禁记录
- 撤销（解封）封禁
- 冲突检测：防止同一 SteamID 被重复封禁
- 冲突处理：自己的记录可编辑，别人的记录可申请介入

### 介入申请

- 服主可对其他人的封禁提起申诉
- 提交申请理由
- 查看申请状态（待处理 / 已解决 / 已拒绝）
- 查看申请详情

### 管理员功能

- 审批新用户注册（通过 / 拒绝）
- 启用 / 禁用用户
- 重置用户密码
- 处理介入申请（标记解决 / 拒绝）
- 维护管理员联系方式（QQ / 邮箱 / 其他）
- 查看全站所有封禁记录

### 公开功能

- 无需登录查看公开封禁列表
- 按用户名 / 原因 / SteamID 搜索
- 按 SteamID 精确查询玩家封禁状态

### 系统能力

- 定时检查封禁到期，自动标记为过期
- 封禁变更审计日志
- 健康检查接口
- 完整的 RESTful API

## v1.4 —— 跨服协同与现代化升级

**发布时间**：2026-09-25

**里程碑**：新增封禁列表共享接口、邮箱管理，并完成运行时栈升级

### 新增接口：封禁列表导出

**`GET /api/external/bans`** —— 供服主 / 外部服务获取完整的生效封禁列表

**特性**

- 任意登录用户（服主或管理员）均可访问
- 返回**所有生效中的封禁**，不受"提交人"过滤限制
- 只返回两个精简字段：`steam_id` 与 `reason`
- **不返回**提交人信息、服务器信息、时间等敏感/冗余字段
- 支持 `search` 参数（模糊匹配 SteamID 或原因）
- 支持分页（`offset` / `limit`）

**典型用途**

- PZ 服务器同步脚本拉取全量封禁列表
- 其他游戏服 / 管理面板对接封禁数据
- 服主查看全站生效封禁的"无隐私视图"

### 新增页面：「所有封禁」

**入口**

- 侧栏菜单新增「所有封禁」（服主与管理员均可见）
- 路径 `/all-bans`

**功能**

- 展示全站所有生效中的封禁记录
- 只显示 SteamID 与原因两列
- 不显示提交人信息
- 支持搜索（后端模糊匹配）
- 搜索输入 300ms 防抖，自动重置至第 1 页
- 分页浏览

### 新增能力：邮箱自助修改

**服主自助**

- 个人设置页可修改自己的邮箱
- 支持清空邮箱（留空提交）
- 非空邮箱需满足格式要求
- 非空邮箱必须**全站唯一**
- 修改邮箱**不会**导致强制下线（与改用户名不同）

**权限说明**

- 用户名 / 邮箱：本人可改
- QQ 号：仅管理员可改

### 运行环境升级

**Node.js 20 → 22**

- 前端构建阶段使用 Node 22 LTS
- 更长的支持周期（到 2027-04）

**Nginx 1.21.5 → 1.30.5**

- 升级至最新稳定版
- 支持 `http2 on;` 指令

**启用 HTTP/2**

- 前后端通信全面启用 HTTP/2
- 页面加载更快，多资源并发更高效
- 浏览器 Network 面板 Protocol 列显示 `h2`

### 修复与优化

- 修复前端搜索只过滤当前页、无法跨页搜索的问题（改为后端搜索）
- 清理无用 import
- 统一部分接口路径命名规范

## v1.4.1 —— 安全补丁与凭据轮换

**发布时间**：2026-09-25

**里程碑**：完成第二轮安全审计修复，并轮换所有生产凭据

### 安全修复

**冲突详情越权（高危）**

修复 `GET /api/bans/:id/conflict` 的权限漏洞：

- **修复前**：任何登录用户可查询任意封禁记录的完整信息（含提交人 QQ / 用户名）
- **修复后**：只有以下三类用户可查询
  - 该封禁记录的提交人本人
  - 对该封禁提交过介入申请的用户
  - 管理员（admin）

越权访问返回 `403 Forbidden`。前端冲突协商流程不受影响。

**客户端真实 IP 获取（中危）**

修复 `c.ClientIP()` 在 Docker 反代场景下取到代理 IP 的问题：

- **修复前**：限流按"代理容器 IP"计数 → 所有用户共享一个配额，限流形同虚设
- **修复后**：显式设置 `SetTrustedProxies(["172.16.0.0/12"])`，正确识别 nginx 转发的真实客户端 IP

**刷新令牌有效期（中危）**

缩短 refresh token 生命周期：

- **修复前**：7 天（168 小时）
- **修复后**：24 小时

降低 token 泄漏后的可利用窗口。

### 凭据轮换

**生产凭据全面更换**

数据库密码、Redis 密码、JWT 签名密钥在长期使用后执行一次性轮换，避免历史凭据泄漏造成的风险：

| 凭据 | 更换方式 |
|---|---|
| PostgreSQL 密码 | 随机生成 32 位十六进制字符串 |
| Redis 密码 | 随机生成 32 位十六进制字符串（此前为空） |
| JWT 签名密钥 | 随机生成 64 位十六进制字符串 |

**Redis 启用密码保护**

- 此前 Redis 在 Docker 内网无密码运行
- 现在通过 `--requirepass` 启用密码认证
- 健康检查同步使用密码
- 后端连接配置同步更新

**影响说明**

- 所有用户的登录态在密钥轮换后失效，需重新登录
- 用户数据、封禁记录、服务器信息完全不受影响

### 运维增强

- 部署流程自动化：凭据轮换、密码同步、服务重建均由脚本完成
- 支持一键回滚：配置文件、环境变量、compose 定义均有备份
- 健康检查覆盖：数据库、缓存、后端服务、HTTP 响应
