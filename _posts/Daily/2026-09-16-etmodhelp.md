EventTrigger（以下简称 ET）是一个 Project Zomboid Build 42 的模组。它允许管理员在地面放置两类"感应点"，玩家靠近时自动触发聊天消息或完成物品交换。<!--more-->

## 模组概览

ET 提供两个核心对象与一个管理界面：

| 对象                         | 作用                                  | 触发方式            |
| ---------------------------- | ------------------------------------- | ------------------- |
| **触发器（Trigger）**        | 玩家靠近时输出一条聊天消息            | 进入范围自动触发    |
| **配送点（Delivery Point）** | 玩家靠近后确认，用背包物品交换奖励    | 靠近提示 → 确认交换 |
| **管理器（Manager）**        | 表格化查看 / 编辑 / 删除 / 重置所有点 | 右键菜单打开        |

**核心特性**：

- 触发器：延迟、范围、最大触发次数、**8 种输出模式**、全局冷却
- 配送点：需求物品门槛 + 消耗物品扣除 + 奖励物品，语义分离，每人上限、按玩家冷却
- 配送点支持**多奖励方案**（同消耗选一奖励）与**多消耗选项**（同奖励选一消耗）
- 每条记录可**停用/启用**（停用后不触发），底部一键**全部停用**
- `Delete All` 需输入 `YES` 二次确认，防止误删
- 全按钮化设置向导，无需记忆命令格式
- **仅面向多人服务器**（单机不加载）；MP 下服务器 JSON 权威存储
- 仅管理员可用（右键菜单），无需任何鉴权道具
- 完整**中文本地化**（简体 / 繁体 / 英文，跟随游戏语言自动切换）

## 安装与依赖

### 必需依赖

- **ElyonLib**：JSON 持久化库（`require=ElyonLib`）

### 可选依赖

- **MongooseChat**：聊天频道集成。已安装时，`/say` `/do` `/low` `/yell` `/ooc` 走对应语音频道与气泡，Named / Broadcast 走蓝色系统频道。未安装时自动回退到原版 ISChat 或头顶 Halo。

### 版本要求

- 游戏版本：Build 42（`pzversion=42`）
- 最低版本：42.19（`versionMin=42.19`）

### 服务器启用

在服务器配置（`servertest.ini` 等）中确保包含：

```ini
Mods=EventTrigger
Mods=ElyonLib
```

`id` 必须与 `mod.info` 中的 `id=EventTrigger` 一致。

## 快速上手

1. **管理员**在多人服务器中进入游戏（本模组**仅多人服务器加载**，单机不生效）。
2. **右键点击地面**，弹出菜单包含三个入口：
   - `Place Trigger (x,y,z)` — 放置触发器
   - `Set Delivery Point (x,y,z)` — 放置配送点
   - `EventTrigger Manager` — 打开管理器
3. 按向导一步步填写参数，完成后点即生效。
4. 玩家靠近触发器自动触发；靠近配送点会收到提示，确认后交换物品。

> 普通玩家（非管理员）不会看到任何 ET 右键菜单项。

## 触发器详解

### 放置流程

右键地面 → `Place Trigger`，向导共 6 步（每步可 `Back` 返回上一步，已填值保留）：

1. **Delay（延迟）**：触发后延迟多少秒再输出消息，整数 0~3600，0 = 立即。
2. **Range（范围）**：感应半径（格），最小 0.5，支持小数。
3. **Max Triggers（最大触发次数）**：`-1` = 无限，`0` 会被自动修正为 `-1`。
4. **Message（消息）**：触发时显示的文本。
5. **Output Mode（输出模式）**：8 种模式按钮选择（见下表）。
6. **Cooldown（冷却）**：触发后的全局冷却（见冷却章节）。

若输出模式选 **Named** 或 **Broadcast**，会额外要求填写 **Display Name**（显示名）。

### 输出模式对照表

| 模式                       | 效果                | 可见范围          | 备注                              |
| -------------------------- | ------------------- | ----------------- | --------------------------------- |
| Named (local only)         | 蓝色系统频道        | **仅本地显示**    | 需要 MongooseChat；显示名可自定义 |
| /say (with bubble)         | 普通说话 + 气泡     | 范围内所有玩家    | 触发者身份                        |
| /do (narration)            | 环境叙述            | 范围内所有玩家    | 无气泡                            |
| /low (whisper)             | 低语 + 气泡         | 近距离            | 范围内所有玩家                    |
| /yell (shout)              | 喊叫 + 气泡         | 大范围            | 范围内所有玩家                    |
| /ooc (global)              | 全局 OOC            | 全服可见          | 范围内所有玩家                    |
| Above Head (local only)    | 头顶漂浮文字        | **仅本地显示**    | 不写入聊天记录                    |
| Server Broadcast (named)   | 服务器广播          | **全服可见**      | 可自定义显示名                    |

> **Named / Above Head 仅触发者本人可见**；需要让全服玩家都看到时，请使用 **Server Broadcast**。

### 触发规则

- 玩家与触发器**同一层（z 相同）**且距离 < Range 时触发。
- 同一玩家在范围内只触发一次，离开范围后重新进入会再次触发。
- 受 Max Triggers 与全局冷却限制，冷却期内任何玩家都不触发。
- 触发器被**停用**（`enabled = false`）时不会触发。

## 配送点详解

### 放置流程

右键地面 → `Set Delivery Point`，向导共 10 步：

1. **Hint Text（提示文字）**：玩家靠近时头顶显示的文字。
2. **Radius（范围）**：感应半径格，最小 0.5。
3. **Max Players（最大玩家数）**：`-1` = 无限，限制能参与的唯一玩家数量。
4. **Max Per Player（每人上限）**：`-1` = 无限，限制每个玩家的配送次数。
5. **Match Mode（匹配模式）**：`ALL` 或 `ANY` 按钮（见下）。
6. **Cooldown（冷却）**：按玩家冷却（见冷却章节）。
7. **Branch Count（方案数量）**：多奖励方案数量，`1` = 单方案。
8. **Required Items（需求物品）**：资格门槛（见"三种物品"章节）。
9. **Consume Items（消耗物品）**：实际扣款的物品，多个时玩家任选其一。
10. **Reward Items（奖励物品）**：玩家获得的物品。

物品选择界面左右两列：左列浏览背包，右列已选列表；支持翻页、数量调整（Qty）、移除（Remove）、**Refresh** 刷新背包、**Back** 返回上一步。

### 三种物品：需求 / 消耗 / 奖励

配送点把"资格"与"扣款"彻底分离，配置时是三个独立步骤：

| 类别                      | 作用                       | 是否扣除                     | 多选语义                     |
| ------------------------- | -------------------------- | ---------------------------- | ---------------------------- |
| **需求物品 Required**     | 资格门槛（ALL/ANY 判断）   | 由 **Collect** 开关决定      | ALL=都要 / ANY=任选其一      |
| **消耗物品 Consume**      | 实际扣款的物品             | 一定扣除                     | 多个时玩家**单选其一**       |
| **奖励物品 Reward**       | 玩家获得的物品             | —                            | 按方案分组                   |

> 一句话区分：**需求物品**决定"有没有资格"；**消耗物品**决定"真正扣什么"。

### 匹配模式

| 模式      | 逻辑                     | 说明                                         |
| --------- | ------------------------ | -------------------------------------------- |
| ALL (AND) | 需要**所有**需求物品     | 每个需求物品都要满足数量                     |
| ANY (OR)  | 需要**任意一个**需求物品 | 满足任一即可                                 |

### 需求物品的 Collect（移除）开关

每个需求物品都有一个 **移除（Collect）** 勾选框：

- **勾选（移除）**：既作为资格门槛，配送时**也会扣除**该物品。
- **不勾选（仅检查）**：只作资格门槛，只检查玩家是否**拥有**该物品，**不扣除**。

配送提示与确认界面会明确标注每项是"（移除）"还是"（仅检查）"。

例：设置"身份卡 x1"为**仅检查**，玩家只需持有身份卡即可反复领取奖励，卡片不会被收走；再设"木材 x5"为**移除**，则每次配送额外扣掉 5 个木材。

### 多奖励方案与多消耗选项

两种扩展可**独立或组合**使用：

- **多奖励方案**（方案数量 > 1）：同一消耗，玩家**选择一个奖励方案**。
- **多消耗选项**（消耗物品 > 1）：同一奖励，玩家**选择一个消耗物品**（只列出背包中持有的）。

玩家依次完成"选方案 → 选消耗 → 确认"后才会执行交换。

### 玩家交互流程

1. 玩家进入配送点范围，头顶显示 Hint Text 与"Delivery Point"提示，并列出需求物品及持有数量（缺失时红字提示）。
2. 弹出 Yes/No 确认框。
3. 点 Yes → 如有多个方案 / 消耗选项，依次弹出选择界面。
4. 确认界面以 2~3 列显示需求 / 消耗 / 奖励物品清单。
5. 点 Confirm → 校验门槛、消耗与冷却 → 扣除消耗物品、发放奖励物品。
6. 背包不足、物品缺失或冷却中会给出红色 Halo 提示。

> **物品匹配规则**：客户端按 `FullType + DisplayName` **严格**校验（能区分你用 `setName` 自定义命名的物品）；服务器按 `FullType` **宽松**执行（避免不同玩家语言环境下物品译名不同导致的误判）。

## 管理器详解

右键地面 → `EventTrigger Manager` 打开表格界面。

### 表格列

| 列                 | 内容                          |
| ------------------ | ----------------------------- |
| #                  | 编号（配送点带 `[D]` 前缀）   |
| Position           | 坐标 (x,y,z)                  |
| Message            | 触发器消息 / 配送点 Hint      |
| Delay/Range/Output | 参数摘要                      |
| Creator            | 创建者                        |
| Triggered          | 触发状态（x次数、DONE/READY） |
| Actions            | 操作按钮                      |

### 行操作

| 按钮              | 作用                                                     |
| ----------------- | -------------------------------------------------------- |
| **Edit**          | 重新打开向导修改（已填值预填充）                         |
| **X**             | 删除该点                                                 |
| **停用 / 启用**   | 切换该点的启用状态（停用后不再触发，位于 X 与 R 之间）   |
| **R**             | 重置（清空触发次数 / 配送记录 / 冷却记录）               |
| **Hist**          | 查看历史（谁在何时触发/配送）                            |

### 底部按钮

| 按钮            | 作用                                                    |
| --------------- | ------------------------------------------------------- |
| Set Delivery Pt | 在当前位置放置配送点                                    |
| Add Trigger     | 在当前位置放置触发器                                    |
| Disable All     | 一键停用所有触发器与配送点（仅管理员）                  |
| Delete All      | 删除（管理员 + Show All 视图 = 全部，否则仅自己的）；**需输入 `YES` 二次确认** |
| Refresh         | 手动刷新（MP 下向服务器请求同步）                       |
| Show All        | 切换显示全部 / 仅自己的（MP 管理员可见）                |
| < / >           | 分页                                                    |

管理器标题栏显示 **Mode: Server**（服务器权威存储，本模组仅支持多人）。

## 冷却时间详解

冷却支持三种模式，时长用"年月日时分"五个字段表示（默认均为 0）：

| 模式       | 含义             | 时钟来源       |
| ---------- | ---------------- | -------------- |
| None       | 无冷却           | —              |
| Wall Clock | 墙钟（真实时间） | `os.time()`    |
| Game Clock | 游戏内时钟       | 世界已运行时长 |

**换算公式**（统一为秒比较）：

```
时长秒数 = ((年×365 + 月×30 + 日)×24 + 时)×60 + 分) × 60
```

**作用范围**：

- **触发器冷却**是全局的（`lastTriggerAt`），冷却期内任何玩家都无法触发。
- **配送点冷却**是按玩家的（`playerCooldowns[pid]`），只限制单个玩家。

选择 None 时，五个时长输入框会禁用。

## 权限说明

- 右键菜单、放置、编辑、删除、停用、管理均**仅管理员**（`getAccessLevel() == "admin"`）可用。
- 本模组**仅面向多人服务器**：单机（SP）下不加载、不生效。
- 无需携带任何物品（已移除旧版 `EventTriggerTool` 鉴权道具）。
- 非管理员玩家只能作为"触发者 / 配送者"被动使用，看不到管理界面。

## 中文本地化

ET 内置完整的多语言支持，跟随游戏语言自动切换：

| 游戏语言 | 显示语言 |
| -------- | -------- |
| 简体中文（CH） | 简体中文 |
| 繁体中文（CN） | 简体中文 |
| 其他语言 | 英文 |

翻译文件位于 `common/media/lua/shared/Translate/{LANG}/UI.json`（标准 PZ 翻译目录）。若需自行改文案，直接编辑对应 `UI.json` 后**完全重启客户端/服务器**（运行中 `reload lua` 不会重载翻译）。

## 数据存储

| 环境    | 触发器存储               | 配送点存储               |
| ------- | ------------------------ | ------------------------ |
| 多人 MP | 服务器 JSON 文件（权威） | 服务器 JSON 文件（权威） |

> 本模组仅支持多人服务器，单机模式不加载、不存储。

多人模式下服务器文件结构：

```
EventTrigger/
├── index.json                 -- 触发器 ID 索引
├── {id}.json                  -- 每个触发器独立文件
├── history/{id}.json          -- 触发器触发历史
└── delivery/
    ├── index.json             -- 配送点 ID 索引
    └── {id}.json              -- 每个配送点独立文件
```

- 每条触发器/配送点含 `enabled` 字段（停用状态持久化，重启后仍保持停用）。
- 删除仅从 index 移除 ID（PZ Lua 无文件删除 API），旧文件成为孤儿，不会再次加载。
- 旧版本 `cooldownType/cooldownValue` 字段会自动迁移到新 `cooldown` 结构，向后兼容。

## 常见问题

| 问题                 | 说明                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| 右键菜单看不到       | 不是管理员；或不是多人服务器（本模组单机不加载）；或 mod 未正确加载（检查 Mods 配置与 id 一致） |
| 触发器不触发         | 检查范围、z 坐标（须同一层）、最大次数是否已耗尽、冷却是否未结束、是否被停用 |
| 配送点不弹出提示     | 检查配送点是否被停用、是否超出每人/最大玩家上限                       |
| Named 模式看不到消息 | Named 与 Above Head **仅本地显示**；要让全服可见请改用 **Server Broadcast** |
| 蓝色频道不出现       | 需安装 MongooseChat；未安装时回退原版聊天                            |
| 交换时提示"缺少物品" | 需求物品（门槛）或消耗物品不足；注意需求物品勾选"移除"时会一并扣除   |
| 交换后物品没被扣     | 确认该物品勾选了"移除"（Collect）；"仅检查"的物品不会被扣除          |
| 界面显示英文         | 游戏语言非中文；或翻译未加载，需完全重启客户端/服务器                 |
| 界面显示 `UI_ET_xxx` | 翻译文件缺失或改名，检查 `Translate/{LANG}/UI.json`                   |
| 改代码不生效         | `require` 缓存或 MP 下服务器需完全重启（见知识库第 18 节）           |
