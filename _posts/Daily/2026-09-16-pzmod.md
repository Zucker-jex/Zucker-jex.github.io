## 0. 快速脚手架：最小可用模组骨架

以下骨架提供了从右键地面到服务器往返的完整链路。复制即用，可用于验证开发环境、测试 MP 通信，或作为新模组起点。

### 目录结构

```
MyQuickMod/
├── 42/
│   ├── mod.info
│   └── media/lua/server/MyQuickMod/Server.lua   -- 服务器入口
└── common/media/lua/
    ├── shared/MyQuickMod/Shared.lua              -- 常量和命令
    ├── client/MyQuickMod/Client.lua              -- UI 和事件
    └── server/MyQuickMod/Server.lua              -- 回退（带 guard）
```

### 文件：`42/mod.info`

```ini
name=My Quick Mod
id=MyQuickMod
description=Boilerplate for B42 modding
pzversion=42
modversion=1.0
```

### 文件：`common/media/lua/shared/MyQuickMod/Shared.lua`

```lua
MyQuickMod = MyQuickMod or {}
MyQuickMod.VERSION = 1
MyQuickMod.MOD_ID = "MyQuickMod"

MyQuickMod.COMMANDS = {
    PING = "MQM_ping",          -- 命令加模组前缀，避免冲突
    PONG = "MQM_pong",
}

function MyQuickMod.IsMultiplayer()
    local world = getWorld()
    return world and world:getGameMode() == "Multiplayer" or false
end
```

### 文件：`common/media/lua/server/MyQuickMod/Server.lua`

```lua
-- 回退文件，带 guard
if MyQuickModServer_loaded then return end
MyQuickModServer_loaded = true

local Shared = require("MyQuickMod/Shared")

Events.OnClientCommand.Add(function(module, command, player, args)
    if module ~= Shared.MOD_ID then return end
    if command == Shared.COMMANDS.PING then
        print("[MQM-SERVER] Received ping from", player:getUsername())
        sendServerCommand(player, Shared.MOD_ID, Shared.COMMANDS.PONG, {
            message = "pong from server",
            time = os.time(),
        })
    end
end)

Events.OnServerStarted.Add(function()
    print("[MQM-SERVER] MyQuickMod initialized")
end)
```

### 文件：`42/media/lua/server/MyQuickMod/Server.lua`

```lua
-- B42 入口文件，设 sentinel，然后 require 公共逻辑
MyQuickModServer_loaded = true
require("MyQuickMod/Server")
```

### 文件：`common/media/lua/client/MyQuickMod/Client.lua`

```lua
local Shared = require("MyQuickMod/Shared")

local dbg = function(...)
    if MyQuickMod.DEBUG then print("[MQM]", ...) end
end

MyQuickMod = MyQuickMod or {}
MyQuickMod.DEBUG = true

-- 右键菜单：发送 PING 到服务器
local function onFillContextMenu(playerIndex, context, worldObjects, test)
    if test then return end
    context:addOption("[MQM] Ping Server", nil, function()
        sendClientCommand(Shared.MOD_ID, Shared.COMMANDS.PING, {
            playerId = Shared.GetPlayerId(getSpecificPlayer(playerIndex)),
        })
    end)
    context:addOption("[MQM] Show Message", nil, function()
        local player = getSpecificPlayer(playerIndex)
        if player then
            HaloTextHelper.addGoodText(player, "Hello from MQM!")
        end
    end)
end

-- 接收服务器响应
local function onServerCommand(module, command, args)
    if module ~= Shared.MOD_ID then return end
    if command == Shared.COMMANDS.PONG then
        local player = getPlayer()
        if player then
            HaloTextHelper.addGoodText(player, "Server: " .. (args.message or "?"))
        end
        dbg("Pong received:", args.time)
    end
end

-- onFirstTick 初始化
local _firstTickDone = false
local function onFirstTick()
    if _firstTickDone then return end
    _firstTickDone = true
    dbg("MyQuickMod loaded")
    Events.OnTick.Remove(onFirstTick)
end
Events.OnTick.Add(onFirstTick)
Events.OnTick.Add(function()
    -- 此处放每帧逻辑（如有）
end)
Events.OnFillWorldObjectContextMenu.Add(onFillContextMenu)
Events.OnServerCommand.Add(onServerCommand)

-- 暴露 GetPlayerId 给 Shared
function Shared.GetPlayerId(player)
    return player and player:getUsername() or "unknown"
end
```

### 部署测试

1. 将 `MyQuickMod/` 放入 `Zomboid/Workshop/` 或 `Zomboid/mods/`
2. 启动游戏，在 Mods 列表中启用 My Quick Mod
3. 进入游戏，手持任意物品右键地面 → 看到 `[MQM] Ping Server` 和 `[MQM] Show Message`
4. 点击 Ping → 头顶显示 `Server: pong from server`
5. 同时服务器控制台输出 `[MQM-SERVER] Received ping from <username>`

这个骨架验证了：目录结构、事件注册、onFirstTick 初始化、SP/MP 兼容、右键菜单、客户端-服务器往返、Halo 输出。新增模组功能可直接在此基础上扩展。

## 1. 模组结构：实际项目中的几种布局

### 官方推荐的分版本布局

```
MyMod/
├── common/
│   └── media/           # 所有版本通用的内容（lua, scripts, textures）
├── 42/
│   ├── mod.info         # B42 清单文件
│   └── media/           # B42 特有内容
└── 41/                  # 可选，仅当支持 B41
```

### 实际项目采用的布局

| 模组          | 布局                           | mod.info 位置     |
| ------------- | ------------------------------ | ----------------- |
| EventTrigger  | `42/` + `common/`（标准）      | `42/mod.info`     |
| BulletinBoard | `42/` + `common/`（标准）      | `42/mod.info`     |
| AVCS42        | 纯 `common/`                   | `common/mod.info` |
| WoWB4213      | `42.14/`（非标准版本号）       | `42.14/mod.info`  |
| ssr_news      | `42/` + `common/` + 根目录冗余 | 各目录一份        |

说明：

- 引擎会扫描 `42.*` 格式的版本目录，WoWB4213 用 `42.14/` 也能识别
- AVCS42 全部放在 `common/` 下依然工作，不强制分版本结构
- `42/media/lua/server/` 路径必须有文件（即使是空文件）让引擎找到服务器入口
- `common/media/` 被所有版本加载，版本特定内容放版本目录下

### EventTrigger（含依赖）

```ini
name=EventTrigger
id=EventTrigger

```

### BulletinBoard（含依赖）

```ini
name=Bulletin Board
id=BulletinBoard
description=Server announcements system
require=ElyonLib
pzversion=42
modversion=1.1
versionMin=42.19
```

### AVCS42（极简，无依赖）

```ini
name=AVCSB42
id=AVCSB42
description=Another Vehicle Claim System
versionMin=42.14.1
```

| 字段         | 说明                                                          |
| ------------ | ------------------------------------------------------------- |
| `name`       | 游戏内显示的模组名                                            |
| `id`         | 唯一标识。服务器 Mods= 行以此为准。**不是 Steam Workshop ID** |
| `require`    | 依赖的模组 ID，强制加载顺序                                   |
| `pzversion`  | 目标 PZ 版本                                                  |
| `modversion` | 模组内部版本号                                                |
| `versionMin` | 最低 PZ 版本要求                                              |

**最常见问题**：服务器 Mods= 行的 ID 与 mod.info 的 `id` 不匹配。

## 4. Lua 事件系统与加载顺序

### 加载顺序

```
media/lua/shared/  → 最先加载，客户端+服务器共享
media/lua/client/  → UI、右键菜单、TimedActions
media/lua/server/  → 仅专用服务器（B42 SP 不加载）
```

每个目录内按字母序加载。

### 事件注册

```lua
-- 正确：传函数引用
Events.OnGameStart.Add(myHandler)

-- 错误：调了函数，注册了 nil
Events.OnGameStart.Add(myHandler())
```

### 常用事件

| 事件                           | 触发时机       | 用途                                 |
| ------------------------------ | -------------- | ------------------------------------ |
| `OnGameStart`                  | 游戏开始       | 初始化模组状态。**联机重连时不触发** |
| `OnTick`                       | 每帧           | 玩家检测、计时器、周期性扫描         |
| `OnPlayerUpdate`               | 每 Tick 每玩家 | 逐帧逐玩家逻辑                       |
| `OnKeyPressed`                 | 按键           | 快捷键处理                           |
| `OnFillWorldObjectContextMenu` | 右键世界对象   | 添加右键菜单项                       |
| `OnServerCommand`              | 收到服务器命令 | 服务器 → 客户端消息                  |
| `OnClientCommand`              | 收到客户端命令 | 客户端 → 服务器消息                  |
| `OnPlayerLogin`                | 玩家连接       | 联机上线同步                         |
| `OnServerStarted`              | 服务器启动完成 | 初始化服务器数据                     |
| `OnPreUIDraw`                  | 每帧 UI 绘制前 | 自定义 2D 渲染                       |
| `EveryOneMinute`               | 每游戏分钟     | 低频定期任务                         |
| `OnClothingUpdated`            | 换装           | 面具/装备检测                        |

### 常用事件注册时机（避免常见陷阱）

```lua
-- ✅ 正确：OnPlayerLogin 在脚本加载时注册，不要在 OnServerStarted 内注册
Events.OnPlayerLogin.Add(onPlayerLogin)
Events.OnServerStarted.Add(function()
    loadData()  -- 只有数据加载延后到 OnServerStarted
end)
```

## 5. 数据持久化：六种方案对比

### 5A. Square ModData

**作用域**：方块级别，随区块保存，所有玩家可见。
**API**：`sq:getModData()` / `sq:transmitModdata()`

```lua
-- WoWB4213 模式
sq:getModData().BBText = "content"
sq:getModData().BBTextColor = { r = 1, g = 1, b = 1 }
if isMultiplayer then sq:transmitModdata() end
```

| 优点                             | 缺点                 |
| -------------------------------- | -------------------- |
| 随地图保存                       | 区块卸载数据不可访问 |
| `transmitModdata()` 保证 MP 可见 | 网络开销随数据量增长 |
| SP 和 MP 接口一致                | 存储空间有限         |

**适合**：位置相关的可视化数据（世界标签、触发器位置）。

### 5B. Global ModData

**作用域**：每角色存档独立。
**API**：`ModData.getOrCreate("Key")`

```lua
-- 读写
local data = ModData.getOrCreate("MyMod")
data.myValue = "something"
```

| 优点                     | 缺点                            |
| ------------------------ | ------------------------------- |
| 始终可访问（无区块依赖） | **MP 中每玩家独立，不自动同步** |
| 随角色保存               | 跨玩家同步需主动广播            |

**适合**：玩家配置、运行时状态、缓存。

### 5C. Global ModData 作为数据库（AVCS42 模式）

AVCS42 用两个 Global ModData key 存储完整的车辆索赔数据库，配合主动广播实现 MP 同步：

```lua
-- 服务器端写
ModData.getOrCreate("AVCSByVehicleSQLID")[sqlId] = {
    OwnerPlayerID = username,
    ClaimDateTime = timestamp,
    AllowDrive = true,
    -- ...
}
ModData.getOrCreate("AVCSByPlayerID")[username] = {
    [sqlId1] = true,
    lastKnownLogonTime = timestamp,
}

-- 不依赖 transmitModdata，用 sendServerCommand 做定向增量更新
-- 每次变更只广播变更的数据："You could transmit the entire Global ModData but
-- that can become bandwidth expensive."
sendServerCommand("AVCS", "updateClientClaimVehicle", updateData)
```

**注意**：EventTrigger 也使用 Global ModData 做备份存储，但 SP 和 MP 的 storage path 不同。SP 使用 Square ModData + Global ModData 备份，MP 使用服务器 JSON 文件。

### 5D. 车辆/物品 ModData（AVCS42 模式）

```lua
-- 车辆 ModData 跨角色、跨存档持久化（因为车辆是世界对象）
vehicle:getModData().SQLID = tonumber(getTimestamp() .. vehicle:getSqlId())

-- 旧方案：存储在"骡子部件"上，自动迁移到车辆 ModData
local mulePart = vehicle:getPartById("Mule")
if mulePart and mulePart:getModData().SQLID then
    vehicle:getModData().SQLID = mulePart:getModData().SQLID
    mulePart:getModData().SQLID = nil
end
```

### 5E. 服务器 JSON 文件（BulletinBoard / EventTrigger V2）

通过 `getFileReader`/`getFileWriter` + ElyonLib JSON。详见 [第 16 节](#16-bulletinboard-案例json-持久化标准架构)。

| 优点                                 | 缺点                  |
| ------------------------------------ | --------------------- |
| 服务器权威，独立于存档               | 仅 MP 有用，SP 不可用 |
| 无区块依赖，全局可访问               | 依赖 ElyonLib         |
| 支持结构化数据（嵌套对象、历史记录） | PZ Lua 无文件删除 API |

### 5F. 文件系统文本文件（ssr_news 模式）

```lua
-- NFO/config.ini + NFO/*.txt
local reader = getFileReader("NFO/config.ini", false)
```

ssr_news 直接用纯文本文件存储新闻内容，服务器每 10 秒轮询文件版本变化。

### 方案选择指南

| 场景                  | 推荐方案                  |
| --------------------- | ------------------------- |
| 位置相关的可视化数据  | Square ModData            |
| 玩家配置、缓存        | Global ModData            |
| 全局数据库，联机专用  | 服务器 JSON 文件          |
| 需要跨存档持久化      | 车辆/物品 ModData         |
| 服务器端纯文本内容    | 文件系统文本文件          |
| MP 中需要广播的数据库 | Global ModData + 主动广播 |

## 6. 客户端-服务器通信

### 6A. 标准模式（BulletinBoard / EventTrigger V2 推荐）

```
客户端 → 服务器: sendClientCommand(module, command, args)
服务器收到: Events.OnClientCommand(module, command, player, args)
服务器 → 客户端: sendServerCommand(player, module, command, args)
客户端收到: Events.OnServerCommand(module, command, args)
```

### 6B. AVCS42 模式（带 player 参数的 sendClientCommand）

```lua
-- 客户端 → 服务器（第一个参数是玩家对象）
sendClientCommand(self.character, "AVCS", "claimVehicle", {vehicle = id})

-- 服务器接收（参数顺序 module, command, player, args）
Events.OnClientCommand.Add(function(module, command, playerObj, arg)
    if module == "AVCS" then
        AVCS.claimVehicle(playerObj, arg)
    end
end)
```

### 6C. 乐观本地执行（EventTrigger 模式）

```lua
function EventTrigger.SendCommand(command, args)
    EventTrigger.ExecuteLocal(command, args)  -- 先本地执行（即时 UI 反馈）
    if EventTrigger.IsMultiplayer() then
        sendClientCommand("EventTrigger", command, args)
    end
end
```

服务器收到命令后执行权威操作，广播 `syncAll` 回所有客户端做最终一致性协调。

### 6D. SP/MP 双模式执行

```lua
-- SP: ExecuteLocal 操作 Square ModData
-- MP: ExecuteLocal 操作本地运行时数组（不碰方块），服务器 JSON 文件为权威源
function EventTrigger.ExecuteLocal(command, args)
    if command == "placeTrigger" then
        if not EventTrigger.IsMultiplayer() then
            WriteToSquare(x, y, z, sqData)  -- SP 写入方块
        end
        table.insert(EventTrigger.triggers, newTrigger)  -- 运行时列表
    end
end
```

## 8. 玩家检测与 Tick 系统

### OnTick 模式

```lua
EventTrigger.tickCounter = 0
EventTrigger.timers = {}

function EventTrigger.OnTick()
    EventTrigger.tickCounter = EventTrigger.tickCounter + 1

    -- 每 300 tick（~5 秒）扫描
    if EventTrigger.tickCounter % 300 == 0 then
        EventTrigger.RebuildList()
    end

    local idx = 0
    while true do
        local player = getSpecificPlayer(idx)
        if not player then break end
        -- 每个触发的距离检测
        idx = idx + 1
    end

    ProcessTimers()
end
```

### 距离计算

```lua
local dx, dy, dz = px - target.x, py - target.y, pz - target.z
local dist = math.sqrt(dx * dx + dy * dy + dz * dz)
local inRange = dist < range
```

## 10. 背包物品操作与 B42 联机同步

> 本节内容来自 EventTriggerDelivery 经过 50+ 次调试验证的模式。

### 双重匹配（FullType + DisplayName）

```lua
function MatchItem(item, fullType, displayName)
    return item:getFullType() == fullType and item:getDisplayName() == displayName
end
```

两个条件必须同时满足。单靠 FullType 不够（自定义名称不同），单靠 DisplayName 不可靠（语言包差异）。

### 两阶段物品移除

PZ 使用 Lua 5.1，不允许遍历 ArrayList 时修改：

```lua
-- 阶段 1：收集引用（反向遍历，不修改 ArrayList）
local toRemoveList = {}
for _, req in ipairs(requiredItems) do
    local remaining = req.count
    for i = items:size() - 1, 0, -1 do
        if remaining <= 0 then break end
        local item = items:get(i)
        if item:getFullType() == req.fullType and item:getDisplayName() == req.displayName then
            toRemoveList[#toRemoveList + 1] = item
            remaining = remaining - 1
        end
    end
end

-- 阶段 2：安全移除（独立 Lua 表，无迭代冲突）
for _, item in ipairs(toRemoveList) do
    inventory:Remove(item)
end
```

### 奖励回滚

```lua
local created = {}
for _, reward in ipairs(rewardItems) do
    for _ = 1, reward.count do
        local instance = inventory:AddItem(reward.fullType)
        if instance then
            table.insert(created, instance)
        else
            -- AddItem 失败，回滚所有已创建的物品
            for _, c in ipairs(created) do
                inventory:Remove(c)
            end
            return false
        end
    end
end
```

### B42 MP 背包同步：inv:contains 是守门员

经验证的有效模式（参考 PZ Marketplace 源码）：

```lua
-- 服务端操作
for i = items:size() - 1, 0, -1 do
    if item:getFullType() == req.fullType and inv:contains(item) then
        inv:Remove(item)
        sendRemoveItemFromContainer(inv, item)  -- 必须显式同步
    end
end

for _, reward in ipairs(rewardItems) do
    local newItem = inv:AddItem(reward.fullType)
    if newItem then
        newItem:setName(reward.displayName)
        sendAddItemToContainer(inv, newItem)   -- 必须显式同步
    end
end
```

**为什么需要 `inv:contains()`**：B42 有自动同步机制，可能在 `Remove` 之前已移除该物品。没有 contains 检查会操作过期引用，导致幽灵物品。

**调试历史**（50+ 次迭代）：

| 尝试 | 模式                                    | 结果               |
| ---- | --------------------------------------- | ------------------ |
| 1    | 客户端 Remove + AddItem                 | 幽灵物品，重连还原 |
| 2    | 服务器 Remove + AddItem（无同步）       | 客户端不可见       |
| 3    | 服务器 + 仅 sendAddItemToContainer      | 双倍幽灵           |
| 4    | 服务器 + 仅 sendRemoveItemFromContainer | 单幽灵             |
| 5    | 服务器 + 双向同步（无 contains）        | 又双倍幽灵         |
| 6    | 服务器 + 双向同步 + contains            | 正常工作           |

**注意**：网络加速器可能造成重复同步包，幽灵物品在加速器环境下比正常环境更易复现。

```lua
local JSON = require("ElyonLib/FileUtils/JSON")

function readJsonQuiet(filePath)
    local reader = getFileReader(filePath, false)
    if not reader then return nil end
    local lines = {}
    local line = reader:readLine()
    while line do
        lines[#lines + 1] = line
        line = reader:readLine()
    end
    reader:close()
    local content = table.concat(lines, "\n")
    if content == "" then return nil end
    local ok, data = pcall(JSON.parse, content)
    return ok and data or nil
end

function writeJsonQuiet(filePath, data)
    local ok, content = pcall(JSON.stringify, data)
    if not ok then return false end
    local writer = getFileWriter(filePath, true, false)
    if not writer then return false end
    writer:write(content)
    writer:close()
    return true
end
```

## 17. EventTrigger 案例：架构与 Ghost Item 调试

> **EventTrigger 简介**：一个"在地面放置触发器/配送点，玩家靠近即触发"的 B42 模组。
> 触发器支持延迟、范围、触发次数上限、七种输出模式（Named / /say / /do / /low / /yell / /ooc / 头顶 Halo）与全局冷却；
> 配送点支持需求/奖励物品的双重匹配（FullType + DisplayName）、AND/OR 逻辑、每人配送上限与按玩家冷却。
> 数据在 SP 用 Square ModData + Global ModData，在 MP 用服务器 JSON 文件（index.json + 每实体独立 json + history/ 与 delivery/ 子目录）。
> 所有管理操作通过 **管理员右键菜单** 触发（无鉴权道具，普通玩家不显示任何菜单项）。
> 每条记录支持**停用/启用**（停用后不再触发），底部提供**全部停用**；`Delete All` 需输入 `YES` 二次确认。
> UI 全按钮化向导，完整**中文本地化**（`getText` + `Translate/UI.json`，含简中 CH / 繁中 CN / 英文 EN）。

### 命令表冲突预警

`sendClientCommand("EventTrigger", "placeTrigger", args)` 的第一个参数 `module` 区分了模组，所以不同模组用了同样的命令名（如 `"syncAll"`）不会产生冲突——服务器回调会先检查 `module ~= MOD_ID then return`。

**但以下情况会冲突：**

1. **全局字符串未加模组前缀**：如果代码不经 `module` 检查就处理命令，或者模块名过于通用（如 `"Chat"`、`"Sync"`），两个模组可能互相拦截。**推荐所有命令字符串加上模组缩写前缀**，如 `"ET_placeTrigger"`、`"AVCS_claimVehicle"`、`"MQM_ping"`。

2. **全局 Lua 表命名冲突**：如果两个模组都用 `global COMMANDS = {...}` 而不是 `local` 或模组命名空间表，后加载的模组会覆盖前者的表。必须用 `MyMod.COMMANDS = {...}` 或 `local COMMANDS = {...}`。

3. **`Events.OnServerCommand` / `Events.OnClientCommand` 全局监听器**：所有模组共用同一个事件。正确的做法：

   ```lua
   Events.OnClientCommand.Add(function(module, command, player, args)
       if module ~= MyMod.MOD_ID then return end  -- ★ 过滤
       -- 处理命令
   end)
   ```

4. **`sendServerCommand` 广播的 command 名碰撞**：即使模块名正确，如果服务端向所有客户端广播时不包含模块标识，客户端收到后可能无法路由。BulletinBoard 和 EventTrigger 都在 `OnServerCommand` 函数中先检查 `module` 再分发，确保不误接。

### 深水区陷阱

以下两个陷阱在 B42 开发中极难排查，一旦遇到会让开发者陷入"明明改了代码却不生效"或"数据莫名其妙丢失"的绝望中。

#### 陷阱 A：`require` 缓存导致改代码不生效

**现象**：修改了 `shared/` 或 `server/` 下被 `require` 引用的文件，重载 Lua（reload lua 命令）后新代码不运行，旧逻辑依然生效。

**原因**：PZ 的 `require()` 与标准 Lua 一样会缓存加载结果到 `package.loaded` 表。第二次调用 `require("MyMod/Shared")` 直接返回缓存表，完全忽略文件变更。

```lua
-- 首次调用：读取文件、执行、缓存结果
local Shared = require("MyMod/Shared")
-- package.loaded["MyMod/Shared"] = 返回的表

-- 后续调用：直接返回缓存，文件变更不生效
local Shared = require("MyMod/Shared")
```

影响范围：`shared/` 和 `server/` 下的所有 `require` 文件。`client/` 文件由于不使用 `require`（直接加载），不受此问题影响。

**临时解决方案（仅限单机测试）**：

```lua
-- 在 reload lua 前或开发入口处清除缓存
package.loaded["MyMod/Shared"] = nil
package.loaded["MyMod/Persistence"] = nil
-- 重新 require 会读取文件最新内容
local Shared = require("MyMod/Shared")
```

**生产环境的正确做法**：发布前完全重启客户端/服务器进行一次完整加载，不要在运行时依赖热重载加载 `require` 模块。

**特别注意**：在专用服务器上，`reload lua` 控制台命令通常**不会重新加载 `server/` 目录下被 `require` 的文件**。即使清除 `package.loaded` 缓存，服务器端的模块路径扫描机制也可能忽略变更。因此，任何对 `shared/` 或 `server/` 逻辑的修改，在 MP 环境下都建议通过**完全重启服务器**来生效，而非依赖控制台命令。

#### 陷阱 B：JSON 文件写入的并发锁隐患

**现象**：MP 高并发下（多个管理员同时修改公告、多个玩家同时完成配送点交易），部分写入丢失或 index.json 损坏。

**原因**：`getFileWriter` 没有文件锁机制。以下两段代码在**同一帧**内执行时，后一次写入会完整覆盖前一次的结果：

```lua
-- 玩家 A 触发 writeJsonQuiet("trigger/index.json", dataA)
-- 玩家 B 触发 writeJsonQuiet("trigger/index.json", dataB) -- 覆盖 dataA 的变更
-- 结果：玩家 A 的写入丢失
```

**影响最大的是 `index.json`**——因为它聚合了所有实体 ID。每次 CRUD 都要读→改→写 index.json，并发场景下后写的 index 会抹掉先写的变更。

**解决方案：写操作队列（Queue）**

在 `OnClientCommand` 服务器端，将写操作推迟到 `OnTick` 中串行执行，确保同一帧内只做一次磁盘 I/O：

```lua
-- 服务器端：写队列
local writeQueue = {}
local writeScheduled = false

local function flushWriteQueue()
    for _, job in ipairs(writeQueue) do
        local ok = pcall(job.fn)
        if not ok then
            print("[ERROR] Write job failed:", job.desc)
        end
    end
    writeQueue = {}
    writeScheduled = false
end

local function enqueueWrite(desc, fn)
    table.insert(writeQueue, { desc = desc, fn = fn })
    if not writeScheduled then
        writeScheduled = true
        Events.OnTick.Add(function()
            Events.OnTick.Remove(flushWriteQueue)
            flushWriteQueue()
        end)
    end
end

-- 使用：在 OnClientCommand 中延迟写操作到下一帧
enqueueWrite("saveTrigger " .. id, function()
    Persistence.saveOneTrigger(trigger)
end)
```

**EventTrigger 的实际做法**：`recordTrigger` 命令只做内存操作（递增计数、追加历史），**不做广播**，显著降低了并发写压力。完整的 index 写入仅在 CRUD 操作（create/delete/edit）时触发，此时服务器已序列化处理，不会在同一帧收到冲突命令。

**替代方案**：如果数据一致性要求极高，可以将 `index.json` 的更新频率降低为**定时全量重写**（如每分钟写一次），日常只写单个实体文件，避免 index 竞争。

## 19. UI/UX 设计：从 EventTrigger 重构中提炼的实战经验

> 本章完整记录了 EventTrigger 从"一堆 `ISTextBox` 弹窗 + 逗号分隔参数"重构为"按钮化向导 + 自适应表格"过程中踩到的所有 UI 坑与最终方案。每一条都对应一个真实报错或可见的渲染缺陷。

### 19.1 按钮重叠的根因：`ISButton:new` 自动扩展宽度

**现象**：一行放多个按钮时，只要标题稍长，按钮就左右重叠、互相遮挡。

**根因**（`ISButton.lua` 第 493-495 行）：

```lua
function ISButton:new(x, y, width, height, title, ...)
    -- ...
    if width < (getTextManager():MeasureStringX(UIFont.Small, title) + 10) then
        width = getTextManager():MeasureStringX(UIFont.Small, title) + 10;
    end
    o.width = width;
```

按钮会**自动撑宽**到 `标题像素宽 + 10`。如果你按预设宽度累加下一个按钮的位置，而标题实际更宽，按钮就被撑宽、压到下一个按钮上。

**修复**：所有按钮布局改用**流式布局**——创建后读取 `btn.width` 作为下一个按钮的偏移。

```lua
-- 测量按钮真实宽度
function EventTrigger.btnW(title)
    return getTextManager():MeasureStringX(UIFont.Small, title) + 10
end

-- 流式布局：用 btn.width 累加位置
local bx = 14
local function place(title, handler)
    local bw = EventTrigger.btnW(title)
    local btn = ISButton:new(bx, y, bw, h, title, self, handler)
    btn:initialise(); self:addChild(btn)
    bx = bx + btn.width + 10   -- ★ 用 btn.width，而非 bw
    return btn
end
```

**从右向左排列**（用于行内操作按钮）则反向累减：

```lua
local rightEdge = x + w - 6
local del = makeBtn("Remove", handler, rightEdge)
makeBtn("Qty", handler, del.x - gap)
```

### 19.2 中文文本被截断成乱码：`#` 与 `sub` 按字节

**现象**：中文物品名（如"牛仔裤"、".30-30子弹"）被从中间切断，产生 `�` 乱码，列宽判断完全失效。

**根因**：Lua 的 `#` 和 `string.sub` 对 UTF-8 返回的是**字节数**，一个中文占 3 字节。`if #name > 18 then name = name:sub(1, 15) .. ".." end` 会把中文从字节中间切开。

**修复**：按 UTF-8 字符迭代 + `MeasureStringX` 像素测量裁剪：

```lua
function EventTrigger.fitText(text, font, maxWidth)
    text = tostring(text or "")
    local tm = getTextManager()
    if tm:MeasureStringX(font, text) <= maxWidth then return text end
    local ellipsis = "..."
    local avail = maxWidth - tm:MeasureStringX(font, ellipsis)
    local out = ""
    for ch in text:gmatch("[^\128-\191][\128-\191]*") do   -- ★ 按 UTF-8 码点迭代
        if tm:MeasureStringX(font, out .. ch) > avail then break end
        out = out .. ch
    end
    return out .. ellipsis
end
```

### 19.3 勾选框回调崩溃：`ISTickBox` 不传 tickbox 对象

**现象**：点击 checkbox 报 `__le not defined for operand`。

**根因**：`ISTickBox` 的回调签名与 `ISButton` 不同——它**不会把 tickbox 对象作为参数传给回调**。回调实参是 `(target, optionIndex, selected, arg1, arg2, checkbox)`。之前代码写 `function onToggleCollect(tickbox) ... tickbox.itemIndex`，`tickbox` 实际是 optionIndex（数字），`>= 1` 比较触发 `__le`。

**修复**：用**闭包捕获索引**，彻底避开回调签名：

```lua
local itemIdx = i + 1
local cb = ISTickBox:new(cbX, cbY, 18, 18, "", self, function()
    EventTriggerDeliveryItemSelect.onToggleCollect(self, itemIdx)
end)
cb:initialise(); cb:addOption("")
cb.selected[1] = collect
```

### 19.4 `ISTextEntryBox` 必须 `instantiate()` 才能用

**现象**：`entry:getText()` 报 nil。

**根因**：`ISTextEntryBox:initialise()` 只调用父类初始化，**底层 Java 对象（`UITextBox2`）要到 `instantiate()` 才创建**：

```lua
function ISTextEntryBox:instantiate()
    self.javaObject = UITextBox2.new(self.font, self.x, self.y, ...)
    self.javaObject:setTable(self)
    -- ...
end
function ISTextEntryBox:getText()
    return self.javaObject:getText()   -- 没 instantiate 就是 nil:getText()
end
```

**修复**：创建后必须三连：

```lua
local entry = ISTextEntryBox:new(text, x, y, w, h)
entry:initialise()
entry:instantiate()   -- ★ 缺一不可
self:addChild(entry)
```

### 19.5 `ISTextBox` 不处理多行标题（提示与输入框重叠）

**现象**：向导提示文字含 `\n` 时，提示与输入框、按钮叠在一起。

**根因**：`ISTextBox` 内部把标题作为**单行** drawText 绘制，输入框固定在 `height/2`。多行文本会直接压在输入框上。

**修复**：自研多行提示对话框，按行数动态计算布局：

```lua
local lines = {}
for line in (prompt .. "\n"):gmatch("([^\n]*)\n") do
    lines[#lines + 1] = line
end
local promptH = #lines * lineH
local entryY = promptTop + promptH + 14   -- 输入框跟随行数下移
```

### 19.6 表头与数据列错位：比例列布局

**现象**：表格表头与下方数据列横向错位，越靠右偏差越大。

**根因**：表头用"累加 `col.w`"定位，数据行用"固定 `col.x`"定位，两套坐标系。

**修复**：**比例列布局**——按窗口宽度百分比计算 7 列，表头与数据共用同一 `cols` 表：

```lua
function EventTriggerUI:computeCols()
    local ratios = { 0.04, 0.15, 0.24, 0.20, 0.10, 0.08, 0.19 }
    local cols, x = {}, self.listX
    for i, r in ipairs(ratios) do
        local w = math.floor(self.listW * r)
        cols[i] = { x = x, w = w }
        x = x + w
    end
    return cols
end
```

表头绘制与 `addRow` 数据定位都读取 `self.cols`，保证任意分辨率严格对齐。

### 19.7 全局 UI 缩放 + 屏幕 clamp

用单一缩放常量，所有窗口尺寸/间距/行高统一乘它，并用 `fitW/fitH` clamp 到屏幕 94% 防止小屏溢出：

```lua
EventTrigger.US = 1.5   -- 全局缩放，改一个数全局生效

function EventTrigger.fitW(baseW)
    return math.min(math.floor(baseW * EventTrigger.US), math.floor(getCore():getScreenWidth() * 0.94))
end
function EventTrigger.fitH(baseH)
    return math.min(math.floor(baseH * EventTrigger.US), math.floor(getCore():getScreenHeight() * 0.94))
end
```

### 19.8 字段名与方法名同名：回调递归崩溃

**现象**：点取消报 `attempted index: close of non-table: null`。

**根因**：构造函数把回调存到 `o.onOk` / `o.onCancel`，而类方法也叫 `onOk` / `onCancel`。当回调为 `nil` 时，`self.onCancel` 经 metatable 回退到**方法本身**，`self.onCancel()` 无限递归。

**修复**：回调字段改用无歧义后缀，并用**点号**调用（冒号会多传 `self` 污染参数）：

```lua
o.onOkCallback     = onOk     -- ★ 字段改名
o.onCancelCallback = onCancel
o.onBackCallback   = onBack

function EventTriggerTextPrompt:onOk()
    self:close()
    if self.onOkCallback then self.onOkCallback(text) end   -- ★ 点号调用
end
```

### 19.9 局部变量作用域陷阱：`:new` 定义了 `gap`，`:create` 里却是 nil

**现象**：打开对话框报 `__add not defined for operands`。

**根因**：`gap` 在 `:new()` 里定义（`local gap = 16`），但没存到对象上，`create()` 里又用了 `backW + gap + okW ...`，此时 `gap` 是 `nil`。

**修复**：`create()` 顶部重新定义所需局部变量，或在 `:new()` 里把布局参数全部存到对象上（推荐后者，见 19.10 的组件写法）。

### 19.10 按钮化向导：三个通用对话框组件

将"有限选项"全部按钮化，避免 `"参数1, 参数2, 参数3"` 这类易错的逗号分隔输入。

#### ① `EventTriggerChoicePrompt` — 按钮单选

用于输出模式（7 项）、匹配模式（ALL/ANY）等有限枚举。选中的项加 `> ` 前缀：

```lua
local modal = EventTriggerChoicePrompt:new(
    "Output Mode", "Choose how the message is shown",
    choices, currentValue,
    function(value) -- 选中回调
        -- ...
    end,
    onCancel, onBack)
```

#### ② `EventTriggerNumberPrompt` — 数字输入 + 防御非法输入

```lua
function EventTriggerNumberPrompt:onOk()
    local num = tonumber(self.entry:getText())   -- ★ 非数字回退默认
    if num == nil then num = tonumber(self.defaultText) end
    if num == nil then num = 0 end
    if self.opts.integer then num = math.floor(num) end   -- ★ 整数 floor
    if self.opts.min and num < self.opts.min then num = self.opts.min end
    if self.opts.max and num > self.opts.max then num = self.opts.max end
    -- ...
end
```

**`setOnlyNumbers` 的负号陷阱**：`setOnlyNumbers(true)` 会禁止输入负号，因此只有**非负字段**才启用；像 `maxTriggers`（-1 = 无限）这类需要负数的字段要关闭 `setOnlyNumbers`，改用 `tonumber` 校验：

```lua
-- 只有 min 非负时才限制纯数字，允许输入 -1
if self.opts.integer and (self.opts.min == nil or self.opts.min >= 0) then
    self.entry:setOnlyNumbers(true)
end
```

#### ③ `EventTriggerCooldownPrompt` — 冷却设置面板

三个模式按钮（None / Wall Clock / Game Clock）+ 年月日时分 5 个数字输入框（一起显示，默认 0）：

```lua
local COOLDOWN_FIELDS = {
    { key = "years",   label = "Years" },
    { key = "months",  label = "Months" },
    { key = "days",    label = "Days" },
    { key = "hours",   label = "Hours" },
    { key = "minutes", label = "Minutes" },
}
```

选 "None" 时禁用五个时长输入框（`entry:setEditable(false)`），确认时强制写 `mode = NONE`。

### 19.11 向导"上一步"与状态保留

多步向导每步都带 `Back` 按钮，回到上一步并**保留已输入值**：

```lua
-- 进入某步时先恢复已填值
local modal = EventTriggerNumberPrompt:new(
    "Range", "Trigger radius in tiles",
    tostring(p.range or 2),   -- ★ 用 p.range 而非硬编码默认
    onOk, onCancel,
    function() EventTrigger.PromptDelay() end)  -- Back 回到上一步
```

关键：`_pending` / `_setupPending` 状态表在整个向导流程中**持续存在**，各步只在 `onOk` 时写对应字段，Back 时重新读取即可还原。

### 19.12 交付点数据切换时的时序 bug

**现象**：required → reward 切换时，物品列表仍显示 required 的"已选中"状态。

**根因**：`ShowItemSelection(mode)` 里 `_selectionMode = mode` 写在 `ui:initialise()` **之后**，而 `initialise()` 立即触发 `create()` 渲染列表，读到的还是旧 mode。

**修复**：先设置模式，再初始化：

```lua
function EventTrigger.Delivery.ShowItemSelection(mode)
    if EventTrigger.Delivery._selectionUI then
        EventTrigger.Delivery._selectionUI:close()
    end
    EventTrigger.Delivery._selectionMode = mode   -- ★ 提前到 initialise 之前
    local ui = EventTriggerDeliveryItemSelect:new(mode)
    ui:initialise()
    ui:addToUIManager()
    EventTrigger.Delivery._selectionUI = ui
end
```

### 19.13 中文本地化：`getText` + `Translate/UI.json` 的四个硬性约束

**现象**：翻译文件写好、代码换成 `getText("UI_ET_xxx")` 后，界面显示的却是 key 本身（`UI_ET_DIv_Point`），而非中文。

**根因链**（`Translator.java` 反编译确认）——PZ 翻译系统有四个隐藏约束，违反任意一个都会"静默失败"：

#### ① 文件名必须是 `BY_NAME` 白名单

`Translator.loadFiles()` 只遍历 `Translator.BY_NAME`（一张 `LinkedHashMap<String, Map>`）里登记的文件名：`UI` / `IG_UI` / `ContextMenu` / `Tooltip` / `Sandbox` / `Moodles` 等。**自定义文件名（如 `EventTrigger.json`）根本不会被扫描**。

```java
// Translator.loadFiles() 核心
BY_NAME.forEach((name, map) -> forLanguageStack(l -> {
    tryFillMapFromFile(basePath, name, map, l, formatFixer);   // 原版
    tryFillMapFromMods(name, map, l);                           // mod（common/ + 42/ 都扫）
}));
```

#### ② key 前缀决定路由到哪个文件

`getTextInternal` 按 key **前缀**分发到对应 Map：

```java
if (desc.startsWith("UI_")) {          // → ui Map → UI.json
} else if (desc.startsWith("IGUI_")) { // → igui Map → IG_UI.json
} else if (desc.startsWith("ContextMenu_")) { // → ContextMenu.json
// ...
```

所以自定义 key 想用 `UI.json`，前缀必须 `UI_` 开头。ET 用 `UI_ET_xxx`（`UI_` 前缀 + 模组缩写 `ET` + 具体名），既保证路由到 `UI.json`，又避免与原版 `UI_` 系列 key 冲突。

#### ③ 占位符是 Java 风格 `%1` `%2`，且 `getText` 自带替换

PZ 的 `getText` 是 varargs，内部用 `text.formatted(args)` 替换 `%1 %2`：

```lua
-- 正确：直接传参
local txt = getText("UI_ET_Hist_Position", x, y, z)
-- 错误：Lua string.format 不认 %1，会抛错或错乱
local txt = string.format(getText("UI_ET_Hist_Position"), x, y, z)
```

翻译值里写 `"Position: (%1,%2,%3)"`，绝不能用 Lua 的 `%s %d`。

#### ④ 翻译在启动时加载，reload lua 不重载

`Translator.loadFiles()` 在 `Core.ResetLua` / 启动阶段调用。开发中改了 JSON 后，运行 `reload lua` **不会**重新加载翻译，必须**完全重启客户端/服务器**。

**正确姿势总结**：

```lua
-- 1. 文件放：common/media/lua/shared/Translate/{LANG}/UI.json
--    LANG ∈ { EN, CH(简中), CN(繁中), JP, ... }
-- 2. key 命名：UI_ET_xxx（UI_ 前缀 → UI.json）
-- 3. 翻译值占位符用 %1 %2
{
    "UI_ET_Hist_Position": "位置：(%1,%2,%3)",
    "UI_ET_Mgr_Title": "EventTrigger 管理器"
}
-- 4. 调用：getText("UI_ET_Hist_Position", x, y, z)
```

**验证方法**（无头校验 key 完整性）：

```powershell
# 对比代码 getText 的 key 与 JSON key，确保无缺失
$json = Get-Content "Translate/EN/UI.json" -Raw | ConvertFrom-Json
$jsonKeys = $json.PSObject.Properties.Name
# 再 regex 扫描 *.lua 里 getText("UI_ET_...")，比对二者差集
```
